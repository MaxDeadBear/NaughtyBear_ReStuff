## 2. The headline: Ep5 dock flicker — root cause and fix (M4.26)

**Symptom:** fast dark flicker on the water around the Ep5 dock, no consistent
shape, fading with distance, camera-motion-gated, present at 30 and 60fps and
on both GPU backends, absent on retail consoles.

**Root cause (RenderDoc pixel-history proven):** the game renders its
blob-shadow decals (ps `BBA590486A51E72A`, the 1001-index pass) essentially
**coplanar with their receivers** (water, planks) and relies on the GEQUAL
depth test. On Xenos, EDRAM's **24-bit float depth** quantized decal and
receiver to the same value → the test tied *consistently* → stable shadow.
Our D32F preserves sub-quantum differences (measured margins ~ULPs at
`fragZ≈0.002668` vs `preZ≈0.002669`), so the tie became a per-frame rounding
coin-flip as the camera drifted: 2 passes in 25 frames at the probed pixel =
the strobe. Every capture-side instrument was truthful — the inputs really
were bit-identical; the nondeterminism lived in the depth compare's last bit.

**Fix:** `native_vk.cpp` M4.26, next to the old M3.26 ZBIAS block — depth bias
on the decal pipeline only (keyed by ps hash), `depthBiasConstantFactor`
default **16384** (binary-searched live: 32 invisible → 2048 flipped the
strobe polarity, i.e. shadow stable with *light* blinking through → 16384
fully stable, no bleed-through). Env `RESTUFF_DECAL_BIAS` overrides, `0`
disables. The visual result also *restores the console's stable shadow field*
on the water, which our renderer had been mostly suppressing.

**Not covered:** the xenos-emulation path still flickers (it has no such
bias). Native is the shipping path; treat as low-priority. If it ever matters,
the same per-draw bias is the shape of the fix on that side.

**The falsification map** (all measured, all genuinely clean — do not re-hunt):
NaN/Inf in vertex or bone data · torn index/vertex captures · stream/rel cache
staleness (incl. full-extent hashing and full per-frame re-upload) · constants
(light rows c8..c31 both banks, spike-scanned) · per-draw transform (matches
frame-consensus WVP bitwise) · render state + material constants · textures
(decal binds none) · stencil shadow volumes + mask quads (live-skipped, no
change) · winding (register-truth, heuristics off) · clears/holes (magenta
discriminator — but see lesson L1) · frame assembly (zero forced-incomplete
publishes) · surface assignment (zero craters over 2348 frames) · chunk
vanishing (v4 identity: real dropouts are rare LOD churn) · dropped barriers
(fences emitted → no change) · fused FMA (→ no change) · thread
priorities/affinities (honored → no change) · frame rate (30fps → still
flickers; user had to say this three times).

**Lessons worth keeping (also in memory):**
- **L1**: a magenta-clear "hole discriminator" false-negatives when earlier
  draws (water) cover the hole. "Black not magenta" only exonerates missing
  draws if nothing draws behind them.
- **L2**: `restuff_dbg.log` rotates at 5MB (`restuff_dbg.1.log`…); post-run
  copies can capture only the tail. `[ENV]` is also re-stamped periodically —
  the *last* `[ENV]` is not the run start.
- **L3**: smoke tests that only reach the title screen cannot catch gameplay
  perf regressions (the FULL_VB_HASH+VBSTALECHECK 1fps incident).
- **L4**: cmd batch: `echo <hex-ending-in-digit>>file` eats the digit as a
  handle number — use prefix redirect `>>file echo …`.
- **L5**: detector identity keys must not include churning fields (index
  count) or real dropouts become invisible; and "absent exactly one frame"
  undercounts multi-frame events.

## 5. SDK codegen findings — the upstreaming list (do from Linux)

Found during flicker recon; most are real defects independent of the flicker.

1. **Memory barriers emit nothing** — `sync`/`lwsync`/`eieio` compile to no
   code (`builders/system.cpp`), and `lwarx`'s reservation load was a plain
   hoistable dereference (`builders/helpers.h`). PPC `sync` needs an
   mfence-class fence on x86 (TSO doesn't order Store→Load), and nothing stops
   *clang* reordering across the others. Now emitted behind codegen-time env
   `REX_EMIT_FENCES` (thread_fence for sync, signal_fence for lwsync/eieio,
   `__atomic_load_n ACQUIRE` for lwarx). Measured: ~10 sync / 100 lwsync /
   2246 lwarx sites in this title; no perf impact; didn't affect the flicker
   but is correct. **Upstream-worthy.**
2. **`vmaddfp`/`vnmsubfp` are unfused** (mul→round→add→round; real VMX fuses).
   Fused emission behind `REX_EMIT_FMA` (`simde_mm_fmadd_ps`/`fnmadd`),
   requires `-mfma` on recomp TUs (game cmake option `RESTUFF_RECOMP_FMA`,
   plus `simde/x86/fma.h` added to `rex/ppc/context.h`). 1343 sites.
   **Currently deployed build is fused.** Upstream-worthy.
3. **`-ffp-model=strict` never reaches recompiled TUs** — the SDK sets it
   directory-scoped for its own sources; lost through `find_package`.
   Meanwhile generated code toggles MXCSR ~34.5k times. Packaging bug;
   upstream-worthy.
4. Smaller accuracy debt: `vmsum3/4fp128` via `dp_ps` (different summation
   order, 1259 sites); `vpkd3d128` fp16 pack truncates instead of
   round-to-nearest; NORMPACKED64 float→int truncation; `vctsxs/vctuxs` never
   set VSCR.SAT. (A task chip exists for this cluster.)
5. `float16_4` spurious-warning fix (control 3 ≡ 2 for shifts 0–2, verified
   against Xenia) + latent shift-3 `u16[9]` overrun note. Already patched in
   `builders/vector.cpp`.
6. Kernel: `ignore_thread_priorities` / `ignore_thread_affinities` cvars
   default true (game ran with both ignored; honoring them changed nothing
   measurable — the visibility of that A/B lives in the flicker record).
7. M4.9 guest-exception identity logging in `xboxkrnl_debug.cpp` +
   `RESTUFF_GUEST_BREAK_CONTINUE`; M4.12 `[HOSTAV]` VEH logging in
   `core/exception_handler_win.cpp`; M4.25 lazy RenderDoc-API fallback in the
   game (SDK probes for renderdoc.dll before the Vulkan layer loads it —
   worth an SDK fix too).

**Local SDK diffs vs tag v0.10.0** (forward these to git):
`builders/system.cpp` (fence gate) · `builders/helpers.h` (lwarx gate,
`<cstdlib>`) · `builders/vector.cpp` (FMA gate, float16_4 warn fix) ·
